SIGIL

StandardInGamingInputLite

HID Competitive Mapper

This program is allowing to have inputs of physical HID (Human Interface Device) and transfer to outputs of virtual HID for competitive gaming. It's easy to use and the program use programmable scripting user interface. It's my biggest program and there are no bugs, I made it in mind to be a standard, it's the best in every points, but it was a lot of hard works. Let's see...

Considerations About the Program

I've been inspired by FastColoredTextBox, but with a lot of modifications I made for better optimization and design with no bugs. SIGIL (StandardInGamingInputLite) is a lite standard way for using gaming controllers in all PC games with highest level of optimization, even with a lot of HID handles. It corresponds to tiny scripted programs (less than 200 lines) which are using well prepared libraries with all data of inputs and outputs and all simular functions to have easy to script and customize every controls. It's possible to mix every inputs and outputs. This version is my last formalized version. It have the essential libraries to start playing games with a lot of gaming controllers on PC. It also have all the essential options, tools and features. To note, it need to enable notifications, to get notified, go to "Settings > System > Notifications & actions", and then turn on "Get notifications from apps and other senders". To note also, it lack rumble and haptic triggers for simplification, optimization and competitive mind. You can find the showcase here, for some videos demonstration here, and for some tips here.

Note About Going More Deeper and Further

I was able to integrate a scripting automation with a local AI agent inside the program but it removing the pleasure to script by yourself the controllers and the render. By the way, scripting is always a copy/paste from existing scripts and add of some tweaking to the already in use configurations. So it's better to not add an AI agent for these reasons, and the meaning to understand better the programation language with basis on a scripting program you create by your own on the fun subjects which are gaming controllers on PC. Learning is always a source of expertise, and my program is very fun to use for understanding motion controls on video games and all handle of controllers, and it become even more truly for competitive gamers. It would be a shame not to have a choice because I'm unable to play with a keyboard and a mouse nor a Xbox controller to FPS (First Person Shooter). I never use to it, so I prefer motion controls and to have the perfect curve for handle aiming with pleasure and competitive way. So AI would never do it for me and at my place, nor anybody, but I was here, and I did it. To note, I also was able to associate magnetometer with gyro controls, and it's better in term of avoiding drift like a flawless pointer, but it add too much latency for aiming like a competitive gamer, it ask some work around a little bit more to have a competitive program without any latency, like for a camera interpolating a lightning dot.

Best Way Ever to Play

Playing with any controller wanted is asking an optimized program because it's not hardware handle and game handle, there is an intermediary called software handle. This last optimized version with almost all features and controllers, is the ultimate program to play with any controller the way only limited by imagination. Among any other program I made, even the most optimized one like ciine or the most practical one like QuickControl or the most lite one like QuickInput, this last version of SIGIL is filling all perks for conventional controllers. It only lack the handle of a camera like with PGM but I think there's not enough fastest codes to retrieve a tracked light position. Who knows? Nothing compare to IR camera of the Wii Remote of course. So I keep this last version of SIGIL and all its scripts well warm up. You can check these links of my other programs in order to get usefull complementary information. Check also the tips before to get started, under the program. I really advice you to check all of that before being lost and trying anything else. You really will find very usefull information.

Restriction of Usage

For unconventional controllers using Bluetooth Low Energy like Switch 2 controllers, it need to note that the buffalo build need last version of the frameworks, that's why I created QuickInput, otherwise I would have a conflict between the script and the buffalo build, but not when using libraries. By the way it's not made to create buffalo build, but it's made to use well prepared libraries like I made, and in this case there are no conflicts with the script and the classic build using my libraries. If you want the most competitive mapper, you can deal firstly with ciine or QuickControl, and then with QuickInput lastly, considering SIGIL as a data checker and a source code panel for all information. About using all of that in games, you are responsible of what you writting, SIGIL is just a bunch of libraries, and it's like an editor of source codes.
